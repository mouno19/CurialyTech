# Tailwind

The Tailwind v4 bridge, cascade layer order, and utility-class usage backed by system tokens.

## Tailwind

The Tailwind v4 bridge at `@curialy/ui/tailwind-theme.css` maps Tailwind theme variables to system CSS variables with `@theme reference inline`, so utility classes like `text-primary`, `bg-surface`, `border-border`, `rounded-lg`, and `shadow-md` stay in sync with the active theme without emitting competing runtime declarations.

globals.css:
```css
@layer reset, theme, base, cui-base, cui-theme, components, utilities;

@import "tailwindcss/theme.css" layer(theme);
@import "tailwindcss/preflight.css" layer(base);
@import "@curialy/ui/reset.css";
@import "@curialy/ui/styles.css";
@import "@curialy/ui-theme-neutral/theme.css";
@import "@curialy/ui/tailwind-theme.css";
@import "tailwindcss/utilities.css" layer(utilities);
```

Pre-declare every layer before any imports. This keeps reset lowest, Tailwind preflight above reset, component/theme styles in the middle, and Tailwind utilities last so utility classes on `className` can intentionally override component defaults.

A layer's rank is set by the first stylesheet on the page that names it, so this order only holds when `globals.css` loads first. Make it the first import in the root layout or app entry, before any module that imports Curialy UI or theme CSS. That includes the `ui-themes` module generated by `design_system theme add` and any root component that imports a theme's `theme.css`. If a theme stylesheet loads first, Tailwind preflight overrides Curialy UI base styles and theme overrides lose. If `globals.css` cannot come first, move the `@layer` line into its own `layers.css` and import that first instead.

Root layout or app entry:
```tsx
import './globals.css'; // first: declares the cascade-layer order

import {themes, defaultThemeSlug} from './ui-themes';
```

Tailwind classes backed by system tokens:
```tsx
<section className="rounded-lg border border-border bg-surface p-4 text-primary shadow-md">
  <Button label="Save" variant="primary" />
</section>
```

The Tailwind bridge is the concrete example of the general interop pattern: expose another library's semantic API, but point the values at system token variables.

## Add Curialy UI to an app that already uses Tailwind

The recipe in the Tailwind section is a whole `globals.css` for a new app. An app that already uses Tailwind keeps its own file: its `@import "tailwindcss"`, its `@theme` mapping, and its `:root` variables stay as they are. Add one `@layer` line above the Tailwind import and the Curialy UI stylesheets below it.

globals.css (existing Tailwind app):
```css
@layer reset, theme, base, cui-base, cui-theme, components, utilities;

@import "tailwindcss"; /* the app's own entry, unchanged */
@import "@curialy/ui/reset.css";
@import "@curialy/ui/styles.css";
@import "@curialy/ui-theme-neutral/theme.css";

/* The app's own @theme and :root rules stay below, unchanged. */
```

This recipe leaves out `tailwind-theme.css`. The bridge maps Tailwind theme names to system tokens, including Tailwind's own defaults such as `rounded-lg` and `shadow-md`, so in an existing app it changes what the app's own classes paint. Add it only when the app does not use the names it maps.

Curialy UI's theme defines its own CSS custom properties (color, spacing, radius, shadow, font, motion and more), and `design_system docs tokens` has the full list. An app token with one of those names collides in one of two ways. An app `@theme` key takes Curialy UI's value, because `styles.css` sets the tokens on `:root` above Tailwind's `theme` layer: with `@theme { --spacing-4: 1.5rem }`, the app's `gap-4` stays 16px. Marking the block `@theme inline` keeps the app's value in its utilities. An app `:root` variable replaces Curialy UI's value, so Curialy UI's own components change: `:root { --spacing-4: 1.5rem }` widens Curialy UI's spacing step 4 from 16px to 24px. Where the root Theme component sets a token again, such as `--color-warning`, the app's own rules inside it read Curialy UI's value instead. Rename any app token that shares a name.

Put the `@layer` line above the app's `@import "tailwindcss"`, never below it. A `@layer` statement orders only the layer names the page has not seen yet, and the Tailwind import names `theme`, `base`, `components`, and `utilities` as it loads. Below that import, the statement can only add `reset`, `cui-base`, and `cui-theme` after Tailwind's `utilities`. That inverts the cascade: the Curialy UI reset then outranks every utility class in the app, and, for example, removes the borders and padding the app's utilities give its controls. Nothing reports it: the build and the browser console stay clean, and the `@layer` line still looks right in the source, so only the rendered page shows the problem.

The load-order rule from the Tailwind section still applies: `globals.css` must be the first stylesheet the page loads, so its `@layer` line names the layers first.
